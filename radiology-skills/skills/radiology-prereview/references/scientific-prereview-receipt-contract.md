# Canonical scientific-prereview receipt contract

Interface version: `1.2`

Use this receipt after a scope-aware scientific prereview or re-review. It freezes what was actually
reviewed and the yardstick handed to response and submission; it is not an author assertion that the
paper is scientifically true or accepted.

## Scope route

| Study scope | Required review route | Minimum scientific ownership |
|---|---|---|
| `imaging-only` | `imaging-panel` | imaging/reproducibility role |
| `mechanism-only` | `mechanism-review` | mechanism role via `radiology-radiogenomics` |
| `imaging-mechanism` | `combined` | both imaging/reproducibility and mechanism roles |
| `evidence-synthesis` | `evidence-synthesis-review` | evidence-synthesis role via `radiology-systematic-review`, with methods/statistics as needed |

Mechanism-bearing scopes require the validated canonical scientific-handoff digest. Every scope
also carries the canonical project-state, modality-role and analysis-lock digests generated by
`radiology-pipeline`, plus the claim-registry digest. These are separate foreign keys: the project
digest excludes only itself, while the modality digest freezes schema/study/scope and the four role
groups.

For `evidence-synthesis`, `scientific_handoff_digest` is exactly `not-applicable`; do not create a
radiogenomics dependency. The receipt instead binds one versioned source artifact for each role:
`protocol`, `search`, `selection-flow`, `extraction`, `risk-of-bias-applicability`, `synthesis`, and
`certainty`. These roles must resolve to the frozen review packet and its exact versions/SHA-256s.
A manuscript alone, a protocol alone, or an author-reported forest plot cannot close this route.
The review checks study-family/report/effect-row hierarchy, overlap/dependence, deviations, pooling
feasibility, uncertainty, certainty and the `synthesized` claim ceiling before editor synthesis.
Use `../templates/evidence-synthesis-source-artifacts.template.json` as the conditional source-row
starter, then copy all seven rows into the canonical receipt and replace every blank identifier,
version and SHA-256. The conditional starter is not itself a receipt and cannot be submitted to the
receipt validator.

## Finding and closure contract

Every frozen finding carries:

`finding_id | severity | criterion | affected_claim_ids | source_artifact_id |
source_artifact_sha256 | evidence_anchor | minimum_repair | closure_evidence_required |
repair_owner | next_gate | source_review_state | prior_verification_state | verification_state |
verification_evidence_locator | state_change_evidence | residual_boundary | required_for_pass`

Stable Finding IDs and affected Claim IDs do not change during re-review. `VERIFIED`, `PARTIAL`,
`NOT_VERIFIED`, `MADE_WORSE` and justified `NOT_APPLICABLE` are finding-level verification states.
A previous `NOT_VERIFIED` cannot be upgraded by response prose, author attestation or a changed
global label; a version-bound `<registered artifact_id>:<locator>` and explicit state-change evidence
are required. It also cannot be relabelled `NOT_APPLICABLE` to bypass closure.
`source_review_state` is immutable across re-review and uses `VERIFIED`, `PARTIAL`,
`NOT ADDRESSED`, `MADE WORSE`, `NOT VERIFIABLE`, or canonical-receipt `NOT_VERIFIED`; it is not the
same axis as the current closure state. Every P0/P1 is necessarily `required_for_pass=true`; only a
P2 may be explicitly advisory. `repair_owner` names the accountable scientific role or skill, not
merely “authors”; `next_gate` names the receiving verification or release gate. Neither field proves
that the repair occurred or that the receiving gate passed.

The global result is exactly one of:

- `SCIENTIFIC_PREREVIEW_PASS`
- `SCIENTIFIC_PREREVIEW_CONDITIONAL`
- `SCIENTIFIC_PREREVIEW_FAIL`

PASS requires zero unresolved placeholders and no required finding left `PARTIAL`, `NOT_VERIFIED` or
`MADE_WORSE`. It remains separate from response-package assembly and all-files submission readiness.

## Canonical digest

`scientific_prereview_receipt_digest` is SHA-256 of canonical UTF-8 JSON after removing only that
top-level digest field. Canonical JSON sorts keys, uses compact separators and rejects non-finite
numbers. It is a semantic receipt digest, not the physical JSON file SHA-256.

Create from `../templates/scientific-prereview-receipt.template.json`, then run:

```text
python scripts/validate_scientific_prereview_receipt.py <receipt.json> --write-digest
```

Any finding, state, Claim ID, source artifact, closure evidence or upstream digest change invalidates
the receipt. The response package preserves both the source and post-revision receipt digests; the
submission intake consumes the current stage-appropriate digest as an upstream foreign key.

# NSFC application content playbook

Read this when developing or reviewing an NSFC title, abstract, 立项依据, 研究内容, 研究基础,
innovation claim or proposal spine. These are scientific functions and review heuristics, not fixed
NSFC headings, word counts or a promise of funding.

## First decide the programme logic

Use the named programme's current official positioning and live form. At a high level:

| Programme | Development emphasis | Do not assume |
|---|---|---|
| Young C | a convergent, feasible question; applicant's independent contribution and innovation potential | a shrunken Key programme or unlimited team dependence |
| General | a mature question chain, adequate basis, clear knowledge gain and executable plan | that every project requires three aims or a mechanism hypothesis |
| Key | current guide direction, limited objectives, focus, systematic depth, team/resources and defence logic | that the General/Young C three-block form applies |
| Young A/B | trajectory, representative contribution, future original direction and growth potential | the General/Young C page rule or section map |
| Region | scientific value plus a real regional scientific opportunity | regional need as a substitute for scientific value |
| Major/research plan/joint fund/special call | contribution to the exact programme objective, coupled tasks and call-specific resources | reuse of a generic General proposal |
| Medical clinical programme | clinical observation or bottleneck → key scientific question → basic/clinical/engineering evidence → return to diagnosis/treatment value | a simple treatment comparison or model-building exercise |

## 2026 General/Young C body

The official 2026 snapshot contains three body blocks:

1. **立项依据** — why the research should be done and what value it has;
2. **研究内容** — organized according to the project's own research logic, without the old fixed
   sub-outline;
3. **研究基础** — the applicant's prior accumulation and ability to execute.

The body is in principle no more than 30 pages. This is an `OFFICIAL_CYCLE_SNAPSHOT` for General and
Young C only; verify the live electronic form. A missing legacy heading is not a defect when its
scientific function is present, but the reform does not license missing objectives, methods,
statistics, risk controls or work conditions.

## Title, abstract, keywords and code

- Title: expose the object, central unknown and main scientific relationship; name an algorithm
  only when it is itself the scientific innovation.
- Abstract: `consequential context → exact unknown → preliminary clue/hypothesis → research path →
  expected knowledge gain and bounded value`.
- Keywords: cover the disease/object, central process/question and imaging/mechanism dimension; keep
  them semantically aligned with the year-bound application code and research attribute.
- Read all field and character limits from the live system. Do not invent a five-sentence abstract,
  a universal title length or a mandatory keyword count.

## 立项依据: evidence-driven argument

It must answer:

1. Why is the problem consequential?
2. What exactly can current knowledge not explain, measure, distinguish or predict?
3. What do the strongest and closest competing studies support or challenge?
4. Why do the applicant's verified preliminary clues make the next test justified now?
5. What testable knowledge will exist if the project succeeds?

Do not write a chronological author-by-author literature catalogue. Include foundational, recent,
contradictory and directly competing evidence in the amount needed to establish the gap. Every
reference, author list, title, year, page and DOI requires human verification.

## Keep the concepts separate

| Concept | Function | Common category error |
|---|---|---|
| Scientific question | unknown mechanism, relation, law or boundary condition | “how to build a multimodal model” |
| Hypothesis | provisional testable answer; not mandatory for every exploratory or metrology study | a guaranteed benefit claim |
| Objective | knowledge or capability established at project end | an activity list |
| Research content | work package used to answer the objective | software pipeline stages labelled as scientific aims |
| Key scientific problem | cognitive bottleneck that determines whether the objective can be answered | an engineering implementation issue |
| Method | means of acquiring evidence | novelty or scientific question |

Use one evidence contract per content block:

`question/hypothesis → population/data and independent unit → comparison/control → primary
estimand/outcome → analysis and decision rule → confirming and disconfirming results → risk and
scientifically meaningful fallback → licensed inference and claim ceiling`.

Avoid “Aim 1 collect/build, Aim 2 optimize, Aim 3 validate” unless each stage tests a distinct
scientific proposition.

## Innovation test

Compare against the closest, strongest current work:

- what it can already do;
- where and why it fails;
- what concept, mechanism, measurement ability or inference boundary changes here;
- what verified preliminary evidence makes the change feasible.

“First Transformer,” “multimodal fusion,” “SHAP,” “domestically absent” and “internationally
leading” are not sufficient scientific innovation claims.

## Feasibility and research basis

Feasibility must cover access and permissions, usable cohort arithmetic, preliminary evidence,
measurement and label reliability, controls, statistical decision logic, ethics/follow-up/device
risk, personnel effort and a fallback that still answers a meaningful question.

Map each preliminary result to the aim it supports and risk it reduces. Separate completed evidence,
ongoing funded work and planned work. A publication list, prestigious platform or asserted PACS
volume cannot by itself establish feasibility.

Use knowledge/evidence milestones rather than “buy equipment,” “complete modeling” or “publish N
papers.” Publications, patents and trainees are outputs; they do not substitute for the scientific
inference.

## Review output

For each material weakness report:

`proposal locator | scientific function | evidence state | consequence for the funder criterion |
smallest valid author decision/repair | residual uncertainty`.

Label all suggested application language `AI_ASSISTED_ADVISORY — applicant must verify and rewrite`
for a live 2026 NSFC route.

# Reviewer response audit gate

Use this reference after drafting a point-by-point response, before sending the revision to the
journal, or when reviewer comments are numerous, conflicting, or analysis-heavy. Declare
`audit_mode: working | final`. Working mode may expose pending items; final mode is fail-closed and
requires `unresolved_placeholder_count = 0`.

Before item-level closure, preserve the frozen global result and use
[prereview-response-state-crosswalk.md](prereview-response-state-crosswalk.md). The receipt records
both `source_scientific_prereview_state` and `post_revision_scientific_prereview_state`; a source
PASS does not close response items, while a post-revision state other than
`SCIENTIFIC_PREREVIEW_PASS` blocks `READY_FOR_SUBMISSION_ASSEMBLY`.
Each state must travel with its canonical `scientific_prereview_receipt_digest`; a hand-entered
three-state label is not a valid foreign key. The response validator loads both receipt JSON files;
it does not trust copied digest strings or item rows by themselves.
The response receipt also carries the current canonical `project_state_digest` and
`modality_role_digest` generated by `radiology-pipeline/scripts/compute_project_state_digests.py`.
They freeze the full project state and the exact schema/study/scope/four-role subset respectively;
neither may be reconstructed from response prose or treated as a physical-file SHA-256.

## Response ledger

Record editor instructions first, then reviewer comments. Every item receives a row:

| Canonical issue ID | Source occurrence ID | Parent ID | Round | Source document/version/digest + locator | Reviewer label | Lineage / prior IDs | Quote status | Comment summary | Request class or N/A—NON_ACTIONABLE | Editorial obligation + editor locator | Author decision + authority source/approver/date | Action | Required result/evidence | Planned manuscript location |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| CI-001 | RR1-R1-1a | CI-001-P | RR1 | decision-v1 SHA256:… p.2 | Reviewer 1 | new / — | bounded excerpt | External validation concern | manuscript-grounded-defect | MUST_FIX / editor p.1 | partially accept / lab meeting / PI / 2026-08-22 | SOFTEN_CLAIM / VALIDATE | frozen model metrics or explicit boundary | Abstract, Results, Discussion |
| CI-002 | RR2-R2-3 | — | RR2 | review2-v1 SHA256:… p.4 | Reviewer 2 | reopens / CI-002 | labelled paraphrase | Calibration requested | clarification-needed | UNKNOWN / — | accept / author email / PI / 2026-08-22 | REPORT_EXISTING | calibration slope/intercept and plot | Results, Fig. 3 |

Use `E-1`, `E-2` for canonical editor issues and round-aware source occurrence IDs such as
`RR2-R1-3`. Use `ROUND_UNKNOWN`, never a guessed round, when sequence cannot be recovered. An editor
instruction cannot disappear merely because no reviewer repeated it. `MUST_FIX`, `SHOULD_FIX` or
`CONSIDER` requires a bounded decision/editor quote and locator; otherwise use `UNKNOWN`.

## Commitment ledger

Extract each concrete promise from the drafted response and verify it against the revised package:

| Commitment ID | Parent/prior IDs | Frozen criterion | Action code | Author response claim | Evidence origin | Verified action/method | Verified result/evidence | Artifact ID/version/digest + locator | Verification method/verifier | Artifact fulfillment | State-change evidence | Residual boundary |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

Use one internal artifact state machine:

- `VERIFIED`: the frozen criterion is satisfied by the manifest-bound artifact, method, actual result,
  claim consequence, residual boundary and all required children;
- `PARTIAL`: only a named part is verified and the remaining boundary is visible;
- `NOT_VERIFIED`: evidence is absent, pending, author-attested only or cannot be inspected;
- `MADE_WORSE`: the revision introduces a new validity, consistency or claim-strength defect;
- `NOT_APPLICABLE`: praise, duplicate-only occurrence or a scientifically justified no-action item,
  with its governing rationale/canonical cross-reference verified.

Any state upgrade requires `state_change_evidence`; response prose alone cannot change the state. A
parent is `VERIFIED` only when every required child is `VERIFIED`. Optional/preference children may be
`NOT_APPLICABLE` with a criterion-linked rationale. `MADE_WORSE` and `NOT_VERIFIED` block final release.
`EDITOR_CLARIFICATION_REQUESTED` always remains `NOT_VERIFIED` and blocks release until the editor's
versioned answer is incorporated and the affected obligations are re-adjudicated.

Keep two separate non-scientific axes:

- `editorial_disposition`: `UNKNOWN | REVIEWER_ACKNOWLEDGED | EDITOR_ACCEPTED | PUBLISHED`;
- `scientific_validity_certificate`: always
  `NONE—this audit does not certify truth, reviewer agreement or acceptance probability`.

## Factuality lock

Before finalizing each response, verify:

- The claimed analysis/experiment was actually performed.
- The response reports the method and result, not merely that work was performed.
- Reported numbers match the revised manuscript, tables, and figures.
- In final mode, every page/line/figure/table locator resolves in the manifest-bound final artifact;
  placeholders are permitted only in working mode.
- Every quoted revised passage matches the final manuscript exactly; otherwise label it a paraphrase.
- Every citation that carries argumentative weight in the response—whether pre-existing or newly
  added—passes identity/DOI, exact-statement support, and version/correction/editor-note status checks
  with a screen date; publication alone is not support.
- Reviewer/editor wording is either an exact or bounded source-verified excerpt, or explicitly
  labelled as a paraphrase whose modality, obligation and scope have not been strengthened.
- No response says "we revised accordingly" without describing what changed.
- A limitation is not presented as solved unless it truly is solved.
- Claim strength did not increase unless the corresponding evidence also increased.
- Optional strengthening and reviewer preference were not silently converted into mandatory experiments.

## Action-type evidence payload gate

Apply this independently of the response prose:

- Quantitative analysis requires the estimand, independent unit, comparator, estimate, uncertainty
  and manifest-bound location.
- Experiment requires the biological unit, control, intervention, readout, replication, actual result
  and manifest-bound location.
- Text-only change requires exact before/after wording and a final locator.
- No-new-work requires a declared eligible action code, criterion-linked rationale, versioned existing
  evidence or canonical-response locator, explicit `N/A—NO_NEW_WORK` fields and residual boundary.

Missing payload means `NOT_VERIFIED`; fluent wording cannot upgrade it.

## Two-pass evidence-before-persuasion audit

1. Freeze each original criterion and compare the original and revised manuscript/data/code without
   reading the author's response narrative. Record `VERIFIED`, `PARTIAL`, `NOT_VERIFIED`,
   `MADE_WORSE`, or `NOT_APPLICABLE` against a versioned artifact manifest.
2. Read the response letter only to find evidence that may have been missed. Change the state only
   when the actual artifact supports it; record the evidence that changed the state.
3. Re-run a fresh integrity sweep for cohort counts, independent units, effect directions, claim verbs,
   figure/table numbers, citations, accessions, code/data statements and new causal language.

## Tone rules

- Start with appreciation only when it is natural; do not over-apologize.
- State the action first, then the evidence/location.
- If disagreeing, acknowledge the concern, define the scope, and cite data/guidance.
- Do not make reviewer-facing promises that the manuscript does not fulfill.

## Conflict handling

When reviewers ask for incompatible changes:

| Conflict | Resolution |
|---|---|
| One reviewer asks to shorten; another asks for detail | Put key text in manuscript, full detail in supplement |
| One asks for stronger claim; another flags overclaim | Keep bounded claim and explain evidence boundary |
| New analysis requested but data unavailable | Explain infeasibility, add limitation, provide sensitivity/negative control if possible |

Final package status is `READY_FOR_SUBMISSION_ASSEMBLY` or `NOT_READY_FOR_SUBMISSION_ASSEMBLY`, with
blocking IDs. It is never a scientific-validity or acceptance certificate. If any audit item fails,
return the response letter with a fix list rather than calling it final.

For a final package, instantiate `templates/response-package-receipt.template.json`, keep the source
`finding_id`, non-empty `affected_claim_ids`, criterion, `source_review_state`, artifact foreign key
and `response_closure_state`, and bind the canonical project-state and modality-role digests, then run
`scripts/validate_response_package_receipt.py <receipt.json> --source-prereview-receipt `
`<source.json> --post-prereview-receipt <post.json> --write-digest`. The canonical
`response_package_digest` binds the receipt semantics and artifact registry; it is distinct from the
physical receipt file SHA-256. A receipt or bound-artifact change invalidates the digest and reopens
the gate. A `VERIFIED` or `PARTIAL` closure locator must use
`<registered artifact_id>:<locator>`; free prose is not closure evidence.

`READY_FOR_SUBMISSION_ASSEMBLY` is a handoff to `radiology-submission`, not an upload verdict. Bind the
final response, clean/marked manuscripts and every revised supporting artifact to the package
manifest, then let the target-journal route independently check current decision-letter/portal file
requirements, extension/container integrity, anonymization and rendered cross-file consistency.

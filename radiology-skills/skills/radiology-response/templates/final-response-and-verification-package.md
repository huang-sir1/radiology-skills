Use only after the relevant actions and results can be verified. Produce two actual files whenever
possible: an editor-facing response letter (Sections A–B) and an internal verification receipt

the explicit `INTERNAL—DO NOT SUBMIT` boundary below.

answering each source occurrence ID. Do not place `FULFILLED`, `READY`, reviewer-satisfaction or
scientific-validity labels in the editor-facing response.

Use the payload required by the action, not generic prose:

- Quantitative analysis: estimand, independent unit, comparator, estimate, uncertainty and location.
- Experiment: biological unit, control, intervention, readout, replication, actual result and location.
- Text-only change: exact before/after claim and location.
- No-new-work route: valid action code, governing rationale, versioned evidence/cross-reference,
  explicit `N/A` fields and residual boundary. Never invent method, result or manuscript change.

Validation requires the two actual prereview receipt files. It rejects a bare state/digest pair,
unregistered or omitted Finding/Claim IDs, immutable-field drift and closure evidence that differs
from the post-revision receipt.

The canonical digest binds every semantic receipt field and artifact digest, including the
pipeline-generated project-state and modality-role foreign keys, while excluding only
`response_package_digest` itself. It is an upstream foreign key for the revision-stage submission
audit, not a physical-file hash or upload-readiness verdict.
